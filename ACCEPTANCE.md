# Acceptance checks

Release `20260905-v2` uses the following acceptance criteria. The measured
verification record and its platform limitations are in `docs/REPRODUCIBILITY.md`.

## Solver structure

- All Python files compile.
- The package-level solver and precision APIs import successfully.
- Source integrity is checked against the release manifest; local environments
  and operating-system metadata are outside the distributed file set.
- Unit tests cover parameter identities, exact-prior moments, cutoff residuals,
  bracket validation, mixture normalization, and the selected public API.

Displayed targets use a tolerance of `1e-6`. PR first-order-condition and
cutoff residuals must be at most `2e-10`. Mixed-TR tie, balance, cutoff, payoff,
and global-support residuals must be at most `2e-9`; all named equilibrium
conditions must pass.
All numerical annotations in Figure 3 must use three significant digits; the
B2 low-design value is displayed as `0.0000356`.

## Output checks

- Each PDF contains one readable page.
- Each PNG is readable and meets the publication-resolution requirement.
- Every CSV cell is bound to its JSON registry (absolute numeric tolerance
  `1e-12`), with exact schema, row order and string checks. Non-finite numbers
  are rejected.
- Each caption contains the notation and numerical comparisons used in the
  figure.
- `python verify_release.py --archive` matches all original distributed bytes,
  excluding the manifest itself and documented local files.
- `sh run_all.sh` succeeds after a rerun even when generated bytes differ; source
  modifications, unlisted distribution files and numerical failures still fail.
