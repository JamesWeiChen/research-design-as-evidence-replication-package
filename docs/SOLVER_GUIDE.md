# Solver guide

## Scope

The public package implements one numerical model: the selected fixed-design
solver, its PR and TR equilibrium routines, and the finite-support common-cutoff
mixed-TR extension required for Figure 3.

## Primitive objects

`Params` stores the paper's primitives. Under the quadratic defaults,

\[
\delta(d)=\delta_0d^2,
\qquad
C_0(d)=\frac{c_d}{2}d^2,
\]

\[
\omega(d)=
\frac{c_p+\delta(d)}
     {c_p+\delta(d)+c_a\beta^2},
\qquad
Y(d)=\sqrt{\frac{2V}{c_a\omega(d)}}.
\]

The prior enters only through mass, moments, centered window moments, and
integration over half-open intervals `(lo, hi]`. The half-open convention
implements the model's adjustment tie-break at the reach boundary.

The package provides exact `NormalPrior`, `LaplacePrior`, and `MixturePrior`
implementations. `Prior` supports atoms plus a piecewise-linear density, while
`OraclePrior` permits a user-supplied measure with the required operations.

## Fixed-design cutoff

For design `d`, `Model.G(c, d)` evaluates the reviewer's payoff at a marginal
manuscript. If the relevant prior window is charged, the payoff uses its
conditional type distribution. If the window is null, the selected face-value
completion applies.

`Model.cutoff_result(d)` performs these steps:

1. Construct or accept a manuscript bracket.
2. Expand the bracket until the reviewer payoff crosses zero.
3. If custom primitives can make `G` non-monotone, scan the initial bracket for
   a hidden crossing before returning an extended all-accept or all-reject
   status.
4. Bisect the crossing and return the boundary, bracket, residual payoffs,
   window mass, and completion status.

`Model.c_star(d)` returns the resulting cutoff value.

## Scholar best response and TR/PR solutions

`Model.best_response_details(c)` evaluates the scholar payoff on a design
grid, refines every local maximum, groups numerically tied global maxima, and
reports the full argmax hull.

`Model.solve_PR()` maximizes

\[
U_S\bigl(d,c^*(d)\bigr)
\]

over design rigour. `Model.scan_TR()` searches for designs that are global
best responses to the cutoff generated by the same design. Every reported TR
candidate includes a global deviation-gap check.

## Mixed-TR diagnostics

`DesignMixture` sorts support points and normalizes strictly positive weights.
`MixedTRSolver.evaluate_candidate()` checks a proposed common-cutoff candidate:

1. charged on-path natural manuscripts are rejected when required;
2. every support design is a global scholar best response;
3. the cutoff pool is charged, balanced, and acceptable;
4. the common gap below the cutoff is rejected;
5. the lower reach boundary is rejected;
6. the reviewer accepts the sampled upper set;
7. the candidate lies within the stated theorem scope when that status is
   claimed.

`MixedTRSolver.search_two_point()` locates separated branch ties on a manuscript
grid, solves the aggregate balance weight, and evaluates each candidate with
the same checks.

## Precision layer

The main solver first localizes roots and optima robustly. The `precision`
package then improves the reported coordinates:

- `polish_root` uses a guarded secant iteration;
- `polish_argmax` solves a central-difference first-order condition;
- `polish_pure_TR_analytic`, `polish_PR_analytic`, and
  `polish_mixed_analytic` use analytic payoff derivatives for the quadratic
  technology;
- `polish_dcp_dpp` computes the two Figure 3 comparison designs.

Precision routines accept localized seeds. They refine a nearby solution and
do not replace the global grid and diagnostic checks.

## Numerical interpretation

The solver reports numerical diagnostics, not computer-assisted proofs. A
passing status means that all sampled and refined conditions satisfy the
declared tolerances. Users changing primitives should increase mesh sizes,
inspect residuals, and check sensitivity to brackets and starting values.
