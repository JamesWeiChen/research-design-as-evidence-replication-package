# Reproducibility record and release maintenance

## Scope and inputs

Release `20260905-v2` covers Figures 2–3 (B0, A1, B1, B2) and the selected
numerical solver. The associated SSRN working paper was written 2026-08-26,
posted 2026-08-28 and revised 2026-08-29, according to its author-supplied
landing-page metadata. Full-manuscript numeric and theorem coverage has not
been audited. No external data or stochastic simulation is required.

## Verification environment

Verification date: 2026-09-05. Existing Conda `data_analysis`, Python 3.13.12,
macOS 15.7.7 x86_64, Intel Core i7-1068NG7 2.30GHz, 32 GiB RAM.
Project dependency versions are pinned in `requirements-tested.txt`.
This does not establish minimum hardware requirements or compatibility with
all Python versions. No fresh environment restore or cross-platform run was
performed. Numerical libraries and their BLAS builds can affect last-bit results.

The initial audit executed the full calculation in 42.89 seconds. All six
original solver tests and the two figure-specific numerical checks passed.
The original/recomputed JSON comparison covered 171 numeric fields: maximum
absolute differences were 9.6860020004641e-14 for Figure 2 and
4.973799150320701e-14 for Figure 3. All 54 CSV cells agreed with their registry
in both original and recomputed outputs. Captions were byte-identical, and
both rendered figures were inspected. The old master command nevertheless
failed because the file manifest omitted `.gitignore` and treated regenerated
output bytes as immutable.

This release repairs those failures and adds regression checks for every CSV
cell (54 individual corruption scenarios), NaN/infinity, malformed schemas,
source tampering, unlisted files, local environments and external symlinks.
Final verification of the repaired code: a clean copy passed the untouched
archive hash check, both standalone figure validators, and two consecutive
`./run_all.sh` executions in 35.603 and 34.779 seconds. Each full run
passed all 12 tests, both figure computations and all validators, and exited
zero. The tests include 54 CSV corruption scenarios; all were rejected.
CITATION.cff also passed the official CFF 1.2.0 JSON schema. Documentation was
then updated with these measured results and the final manifest rechecked.

The NumPy build reports Apple Accelerate BLAS/LAPACK. Thread-count environment
variables were unset during verification; library defaults applied. Numerical
reproduction is tolerance-qualified, not a claim of byte-identical output on
other platforms. The final archive contains only the explicitly listed release
files and was checked again after assembly.

## Integrity versus numerical reproduction

`python verify_release.py --archive` checks an untouched package against every
hash in `MANIFEST.sha256`. Use it before recomputation. A changed reference file
is an integrity failure in this mode, even when its numerical values are close.

`sh run_all.sh` checks source hashes and metadata, runs regression tests,
recomputes results and validates numerics/captions/figures. It checks source
integrity again on completion. It deliberately allows only the ten explicitly
named generated files to differ from their original byte hashes. The file set
must still match, so missing or unexpected distribution files are errors.

The manifest is not silently regenerated by this workflow. Source changes must
be reviewed and assigned to a deliberate release update. Git internals, local
`.venv`/`venv` environments, Python caches, Finder metadata and the local
`.vscode/settings.json` are excluded; unrelated extra files are not ignored.

## Maintaining a release

1. Make and review source/documentation changes and update VERSION and release
   metadata together. Retain older entries in CHANGELOG.
2. Recompute the registries/figures using the individual README commands and
   run their validators. This avoids the stale source-hash gate during editing.
3. Deliberately regenerate the baseline with
   `python verify_release.py --write-manifest`. Review its file list, then run
   `python verify_release.py --archive` and `sh run_all.sh`.
4. Assemble a separate directory containing exactly the manifest-listed files
   and MANIFEST.sha256, preserving paths. Do not copy Git internals or symlink
   to files outside the deposit. Validate the archive before rerunning there.
5. Record runtime/environment and errors. If documentation is updated to record
   final results, refresh and recheck the manifest for that deliberate update.
   Never refresh a manifest simply to conceal an unexpected difference.

Do not add the analysis machine's entire shared environment or private audit
logs to the deposit. MIT covers this package's original code, documentation and
outputs; dependencies retain their own licenses, and the paper remains separate.
A journal-specific archive/DOI is a publishing step outside local verification.
